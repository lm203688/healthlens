## 二、流程走通性实测

### 急救拦截（本轮真跑）

```
EMERGENCY_KEYWORDS 共 8 类：心血管 / 呼吸 / 神经·卒中 / 出血 / 过敏·休克 / 中毒 / 创伤 / 代谢危机
```

| 输入 | 结果 | 分类 |
|---|---|---|
| `我胸口很痛，呼吸困难` | ✅ 拦截 | 呼吸 |
| `胸痛` | ✅ 拦截 | 心血管 |
| `心悸` | ✅ 拦截 | 心血管 |
| `呼吸困难` | ✅ 拦截 | 呼吸 |
| `胸痛 出汗` | ✅ 拦截 | 心血管 |
| **`胸口疼`** | ❌ **未命中** | — |
| **`我头晕`** | ❌ **未命中** | — |
| **`头疼`** | ❌ **未命中** | — |

**中间件已全局注册**（`app/__init__.py:121-122`），拦截逻辑会在每次 HTTP 请求时执行。

### 🔴 实测发现的两个缺口

| 缺口 | 说明 |
|---|---|
| **1. 关键词表覆盖不足** | "胸口疼"（口语化胸痛）"头晕""头疼"均未命中。8 个类别但词表偏书面语，**口语表述漏检** |
| **2. 前端未呈现拦截结果** | `frontend/src/pages/AgentChat.jsx` **完全没有** emergency / 危急 / 急救 相关代码。前端只调用 `api.agentTeam({user_input})`。→ **后端拦截了，但用户看不到引导，等于白拦截** |

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| 对话入口 | ✅ 好 | 单一输入框，低门槛 |
| **拦截的可见性** | ❌ **致命** | 拦截了却不告诉用户，是最坏的结果——用户以为系统在正常回答健康建议 |
| 拦截的语气 | ⚠️ 待确认 | 急救引导必须**明确、不模糊**（"立即拨打 120"而非"建议就医"） |
| 转诊路径 | ⚠️ 待确认 | 拦截后是否给出就近就医/急诊的具体指引 |
| 多轮上下文 | ⚠️ 待确认 | Agent 是否记住历史（八轴画像、既往建议） |

**最需要改的一条**：**拦截结果必须在前端强提示**（全屏警示或置顶卡片，不可折叠）。这是**安全关键功能**，不是体验优化。

## 四、市场与竞品对标

**需求判断**：需求极真实，但 **C 端入口已被巨头占满**。

| 竞品 | 规模/定位 | 说明 |
|---|---|---|
| 蚂蚁阿福 | 2026-09 用户 **1.5 亿**、日均健康咨询 **1000 万次** | C 端通用问答已被占满 |
| 京东健康 | AI 问诊渗透率 >80% | 同上 |
| 平安好医生 | AI 日问诊数百万 | 同上 |
| OpenEvidence | 3 年 35 亿美元估值 | 医生侧证据检索 |
| Hippocratic AI (Polaris) | 非诊断性随访，与 Epic/MEDITECH/Oracle 集成，已完成 700 万次呼叫 | **非诊断**定位，合规友好 |

**战略结论**：**通用健康问答是死路**；**危急值识别 → 拦截 → 转诊是刚需且合规友好**。
政策依据：国办发〔2026〕11 号《关于加快建设分级诊疗体系的若干措施》（2026-04-09）。

## 五、可融合的开源技术 / 基准

| 项目/基准 | 许可 | 时间 | 能解决什么 | 建议 |
|---|---|---|---|---|
| **MEDHARM** | 论文 + 数据 | 2026-05-26 | **1100 条高危医学查询**，10 个安全关键类别（毒理/药理/隐蔽投毒/麻醉等）红队基准 | **建议引入**：作为上线前与每次模型变更的回归测试 |
| MedGemma-4B 护栏绕过研究 | 论文 | 2026-07-09 | 证明 **reframing 即可绕过护栏** → 不能只靠 prompt/分类器 | **方法论**：针对 reframing 单独建测试用例集 |
| **MCP** | 开放规范 | 2026-07-28 第 5 版（**最大规模修订，含 breaking changes**） | 工具/数据接入标准 | **建议**：把八轴评分、时钟、中医引擎暴露为 MCP 工具 |
| A2A | 开放规范 | v1.0（2026-03-12） | Agent 间协商 | **不建议**：医疗场景下多 agent 协商的审计与责任归属成本过高 |

**取舍**：
- **完全不自研 LLM**。
- **危急值拦截必须是确定性规则 + 阈值表，独立于 LLM 执行**——化验危急值有国家卫生行业标准，自研的是规则表与升级/转诊路径，不是模型。
- 护栏层用 MEDHARM 类基准做回归测试。

## 六、提升方案

### P0（1 周内，安全关键）

| 项 | 动作 | 验收标准 |
|---|---|---|
| **P0-1** | **前端强提示拦截结果**：`AgentChat.jsx` 接收并渲染 emergency 字段，全屏警示/置顶卡片，**不可折叠** | 触发拦截时用户必然看到就医引导 |
| **P0-2** | **扩充关键词表**：覆盖口语表述（胸口疼/心口疼/憋气/喘不上气/晕倒/剧烈头痛等） | 上述测试样例 100% 命中 |
| **P0-3** | **化验危急值阈值表**：接入国家卫生行业标准的危急值项目，独立于 LLM 执行 | 危急值触发拦截并留痕 |

### P1（3–6 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | 引入 MEDHARM 类基准做**上线前 + 每次模型变更**的回归 | 有可执行的评测脚本与通过阈值 |
| P1-2 | 针对 **reframing 攻击**建测试用例集（研究已证明可绕过护栏） | ≥ 30 条 reframing 用例 |
| P1-3 | 拦截后给具体就医指引（就近急诊/120）而非泛泛"建议就医" | 文案明确可执行 |

### P2（2–4 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P2-1 | 把八轴评分/时钟/中医引擎暴露为 **MCP 工具**（**不用 A2A**） | 外部 Agent 可调用 |
| P2-2 | 多轮上下文记忆（八轴画像 + 既往建议） | 对话能引用历史 |
