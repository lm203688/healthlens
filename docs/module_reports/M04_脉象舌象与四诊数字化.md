## 二、流程走通性实测

**主链路**：ESP32 采集 → 边缘盒频谱 → 上送 `hl.pulse.*` → `pulse_engine` 判读 → 多标签脉象 + 八轴信号 + 养生参考

| 环节 | 状态 | 判据 |
|---|---|---|
| 固件 | ✅ 存在 | `firmware/pulse_esp32.ino` |
| 频谱分析 | ✅ 存在且有测试 | `spectrum.py` + `tests/test_spectrum.py` |
| 安全 | ✅ 好 | `command_whitelist.py` 指令白名单 |
| 数据契约 | ✅ 好 | `device_output_contract` + `hl.pulse.*` 命名空间 |
| 云端判读 | ✅ 存在 | `pulse_engine.py` 320 行，输出"多标签脉象 + 八轴信号 + 养生参考 + 健康护栏" |
| 舌象分析 | ✅ 存在 | `tcm_tongue_analyzer.py` 206 行 |
| **临床一致性验证** | ❌ **未见** | 脉象判读结果与中医师判读的一致率，无任何验证装置 |
| **信号质量校验** | ⚠️ 待确认 | 佩戴不良/运动伪迹是否被识别并拒绝 |

**结论**：**工程链路是完整且认真的**（固件 + 频谱 + 白名单 + 契约 + 测试），这在同类项目中少见。但**判定结果的可信度完全没有验证**——这是从"能跑"到"能信"的鸿沟。

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| 需要专用硬件 | ❌ **C 端门槛极高** | 用户要买/装 ESP32 设备才能用，这是**产品级障碍** |
| 舌象拍照 | ✅ 门槛低 | 手机可完成，但受光线、食物染色影响大 |
| 采集反馈 | ⚠️ 待确认 | 是否实时提示"信号质量差，请重新佩戴" |
| 结果可理解性 | ⚠️ | "弦脉""滑脉"对普通用户无意义，需翻译 |

**核心判断**：这个板块的需求本质是 **B 端器械需求，不是 C 端 App 需求**。C 端"手机拍舌象"多为营销噱头，临床可信度弱且监管敏感。

## 四、市场与竞品对标

| 对象 | 定位 | 开源 | 说明 |
|---|---|---|---|
| **上海道生医疗**（2007 起） | 舌面脉信息采集 + 体质辨识系统 | 否 | 院内设备 + 中医馆渠道，走医疗器械路径 |
| 天士力"数智本草" | 2026-05 发布，舌/面/脉多模态数十秒出报告 | 否 | 药企营销导向 |
| 各类 C 端"AI 看舌"小程序 | 拍照测体质 | 否 | 多为营销，监管敏感 |

**市场判断**：需求存在，但**痛点是"准不准 / 能不能被认可"**，不是"有没有"。
**开源侧**：GitHub 上中医舌诊/脉诊项目基本是学生级（0–1★、无许可证），**无可直接采用者**。

### ⚠️ 标准硬约束
**GB/T 20348-2026《中医基础理论术语》** 2026-03-31 发布、**2026-07-01 实施**；同批实施的还有《中医药诊断词汇 第 1 部分：舌象》《第 2 部分：脉象》。
→ **舌象与脉象术语必须对齐该标准**，否则在国标语境下不被承认。

## 五、可融合的开源技术

| 项目 | 许可 | 活跃度 | 能解决什么 | 集成成本 | 建议 |
|---|---|---|---|---|---|
| **NeuroKit2** | MIT | 2.4k★ / 2026-10 | **PPG/ECG/EDA 全流程处理** | 低 | **首选**：替换任何自研滤波/峰值/HRV 代码 |
| HeartPy | MIT | 1.15k★ / 2025-12 | 轻量 HR/HRV（**维护放缓**） | 低 | 可作降级路径 |
| systole | Apache-2.0 | 94★ / 2026-10 | PPG/ECG 校正与心率变异 | 中 | 备选 |
| physio | MIT | 16★ / 2026-05 | 生理信号峰值检测 | 中 | 备选 |
| Pulse-PPG / PaPaGei | MIT | 83★ / 2025-11 | 开源可穿戴 PPG 基础模型 | 中（需 GPU） | 中长期关注 |

**取舍**：
- **直接用开源**：信号处理（NeuroKit2）。**不要自研滤波与峰值检测。**
- **必须自研**：脉象分类（脉位/脉率/脉形 → 中医证候）的标注体系与判读模型——开源完全没有，**且必须做临床一致性验证**。
- **GB/T 20348-2026 术语对齐**：必须自研映射表，无开源可替。

## 六、提升方案

### P0（1–2 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P0-1 | **舌象/脉象术语对齐 GB/T 20348-2026**（含舌象、脉象两个分标） | 输出术语映射表；输出中同时给出标准名与俗称 |
| P0-2 | 信号质量校验：伪迹/佩戴不良→拒绝并返回原因 | 低质量信号不产生判读结果 |
| P0-3 | 结果加"养生参考 / 非诊断"护栏（对齐 M09 claims） | 每次输出带护栏文案 |

### P1（1–2 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | **临床一致性验证**：与 ≥ 2 名中医师对 ≥ 30 例做盲法判读对比 | 输出一致率（Kappa），诚实公开当前值 |
| P1-2 | 用 NeuroKit2 替换自研信号处理 | 有对照测试证明不劣于现有实现 |
| P1-3 | 舌象采集引导：光线、餐后时间、伸舌姿势的明确指引 | 降低无效图像比例 |

### P2（战略决策，需先决策再投入）

| 项 | 动作 | 验收标准 |
|---|---|---|
| **P2-1 战略问题** | **是否有医疗器械注册路径规划？** | 若无 → **明确降优先级，硬件转研究/演示用途**；若有 → 按器械路径补临床验证与质量体系 |

> **明确建议**：ESP32 硬件采集层**不应作为产品主线**。若无器械路径规划，投入产出比远低于 M02（OCR）、M03（连接器）、M06（八轴）。理由：C 端用户不会为脉象买硬件；B 端中医馆已被道生等闭源设备占据，且需要器械证。
