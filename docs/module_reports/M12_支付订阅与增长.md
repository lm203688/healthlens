## 二、流程走通性实测

**主链路**：免费额度 → 触发付费墙 → 选择套餐 → 支付 → 回调 → 开通权益 → 积分/推荐

| 环节 | 状态 | 判据 |
|---|---|---|
| 国际支付（Creem） | ✅ 通 | `/creem/webhook`、`/creem/setup-status`；`query_checkout()` 查单 |
| 国内支付（讯虎） | ✅ 通 | 支持 `wechat` / `alipay` / `xunhu`；`query_order()` 查单 |
| 订单状态机 | ✅ 好 | `payment_method in ("wechat","alipay","xunhu")` 与 `("creem","card","international")` 双分支，均有查单兜底 |
| 免费额度 | ✅ 存在 | `freemium_service.py` 有功能级额度配置（含 `frequency_prescription`） |
| 积分 | ✅ 存在 | `points_service.py` |
| 推荐裂变 | ✅ 存在 | `referral_service.py` + `tiered_referral_service.py`（分层推荐） |

**结论**：功能覆盖完整，且**双通道设计（国际 Creem + 国内讯虎）本身是正确的**。

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| 双通道 | ✅ 好 | 国内外分开，符合实际 |
| **付费墙时机** | ⚠️ 关键 | 若在用户看到价值前就拦截，转化率极低；应在"报告生成后、查看详情时"触发 |
| 免费额度可见性 | ⚠️ 待确认 | 用户是否清楚"还剩几次" |
| 支付失败处理 | ⚠️ 待确认 | 失败后是否有明确重试路径与订单状态查询 |
| 订阅管理 | ⚠️ 待确认 | 用户能否自助查看/取消订阅（**这也是 GDPR/消费者权益要求**） |

**最需要改的一条**：**付费墙时机 + 订阅自助管理**。前者决定转化，后者是合规要求（多地法律要求取消订阅应与订阅同样容易）。

## 四、市场与竞品对标（2026 实测共识）

| 通道 | 性质 | 2026 现状 | 风险 |
|---|---|---|---|
| **Stripe** | 非 MoR | 费率最优，税/VAT 自理 | 合规负担在己方 |
| **Paddle** | MoR | 合规省心，审核偏重 | 审核周期 |
| **Lemon Squeezy** | MoR | **被 Stripe 收购后路线不明**，已有创始人迁出（据 2026-07 测评） | **不建议新接入** |
| **Creem** | MoR | 独立开发者友好 | ⚠️ **2026-03 有账号被封案例 → 单点风险，不可做唯一通道** |
| **微信支付跨境 / Ping++ / Airwallex** | — | 国内通道 | 资质与结汇 |

### 🔴 风险提示
当前国际支付**只有 Creem 一个通道**。研究明确指出 Creem 有 2026-03 封号案例 → **单点依赖风险真实存在**。支付通道一旦被封，收入直接归零且用户无法退款。

## 五、可融合的开源 / 商业方案

| 对象 | 说明 | 建议 |
|---|---|---|
| **Paddle / Stripe** | MoR / 非 MoR | **主通道 + 备份**：Creem 之外必须有第二通道 |
| Airwallex / Ping++ | 中国主体全球收款 + 结汇闭环 | 国内场景 |
| 自托管 referral/affiliate 项目 | GitHub 上有若干（成熟度参差） | 可参考，**但必须加反作弊** |

**取舍**：
- **不自研支付**（用通道）。
- **积分、推荐裂变自研**（强业务耦合，且是产品差异化）。
- **通道必须 ≥ 2 个**（Creem + Paddle/Stripe）。

## 六、提升方案

### P0（1–2 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| **P0-1** | **增加第二支付通道**（Paddle 或 Stripe），与 Creem 互为备份 | 一通道不可用时可切换，不中断收入 |
| P0-2 | 订阅自助管理：查看/升级/取消，取消路径不劣于订阅路径 | 合规要求，有明确入口 |
| P0-3 | 支付失败的可操作重试 + 订单状态自助查询 | 用户能自助解决 |

### P1（3–6 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | **付费墙时机优化**：先给价值（报告概览），再拦截详情 | 有 A/B 数据支撑 |
| P1-2 | 免费额度可视化（剩余次数、何时重置） | 用户清晰可见 |
| P1-3 | **推荐反作弊**（自引、设备指纹、异常频次） | 有规则与人工复核通道 |

### P2（2–4 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P2-1 | 分层推荐（tiered）的效果归因与结算 | 有可审计的归因链路 |
| P2-2 | 多币种与税务（VAT/GST）自动处理 | 覆盖主要法域 |
