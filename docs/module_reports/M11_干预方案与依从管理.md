## 二、流程走通性实测

**主链路**：设定目标 → 每日打卡 → 用药记录 → 依从统计 →（可选）方案推演 → 反馈调整

| 环节 | 状态 | 判据 |
|---|---|---|
| 目标 CRUD | ✅ **完整** | 增/删/改/查/进度/统计六端点齐全，`_calculate_progress()` 按 goal_type 计算 |
| 打卡 | ✅ 通 | 创建 + 历史 + 汇总 |
| 用药依从 | ✅ **完整** | 计划 → 记录 → 统计三端点 |
| 模拟器 | ✅ 通 | `wellness_simulator` + `causal_simulator` 均实测可跑（见 M07） |
| **提醒/通知** | ⚠️ 存在 | 有 `notification_service.py`，与依从的联动待确认 |
| **与八轴的联动** | ⚠️ 部分 | `derive_baseline_from_checkin()` 可从打卡推导八轴基线，方向正确 |
| **与 PGx 的联动** | ❌ **未见** | M05 未与用药清单联动（已在 M05 列为 P0） |

**结论**：**后端能力是完整的**（目标 CRUD 六端点 + 依从四端点），这在同类项目中属于偏上水平。缺口在"联动"而非"功能"。

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| 打卡摩擦 | ⚠️ 关键 | 打卡的生死线是**单次耗时 < 10 秒**。若需填多项则必然流失 |
| 目标设定 | ✅ 好 | 有类型化目标与进度计算 |
| 反馈及时性 | ⚠️ | 打卡后是否立即给出可视化反馈（连续天数、趋势） |
| **断连恢复** | ❌ **未见** | 用户中断 3 天后回来，是否有"欢迎回来"的重新激活路径——**这是留存的关键设计** |
| 用药提醒时段 | ⚠️ | 是否允许用户自定义提醒时间与免打扰时段 |

**最需要改的一条**：**打卡必须极简化 + 中断后必须有重新激活机制**。行为科学的共识是：习惯养成靠连续性反馈，中断后的羞耻感是流失主因，应设计"跳过不惩罚、回来有奖励"的路径。

## 四、市场与竞品对标

**需求判断**：真需求，但**红海、低壁垒**。
⚠️ **监管边界**：若触及剂量/禁忌即越界成器械（FDA General Wellness 指南边界），监管风险弱于 M09 但真实存在。

| 竞品 / 参考 | 定位 | 说明 |
|---|---|---|
| Medisafe | 用药提醒 | 商业（最新状态未核实） |
| MyPocketRx | 依从遥测 PDC/MPR、FHIR MedicationStatement 导出 | 商业（实质未核实） |
| pillbutler | 药盒 + 视障人群 | 开源小项目，需配套硬件 |

**成熟开源方案稀缺**。真正该用的是**标准而非项目**：HL7 FHIR `MedicationRequest` / `MedicationStatement`。

## 五、可融合的开源技术 / 标准

| 项目 / 标准 | 许可 | 活跃度 | 能解决什么 | 建议 |
|---|---|---|---|---|
| **FHIR MedicationRequest / MedicationStatement** | 标准 | — | 用药计划与服药记录的标准建模 | **数据模型 100% 采用 FHIR 资源名** |
| **fhir.resources**（Python） | — | 活跃 | pydantic v2 的 FHIR 模型 | 替换自建模型 |
| fhirclient / HAPI FHIR | Apache-2.0 | HAPI 10900+ commits（2026-08 活跃） | 客户端 / 服务器 | 按需 |

**取舍**：
- **不自研提醒引擎**（调度 + 推送用现成）。
- **数据模型 100% 采用 FHIR 资源名**——这是 B2B 互操作的入场券。
- **打卡/目标设定自研**（产品差异化在这里）。
- **频率疗法：降级为音频体验模块，剥离疗效宣称**（见下）。

### 🔴 科学性负资产：频率疗法

`frequency_prescription.py` 提供 174Hz / 528Hz / 396Hz / 40Hz / 741Hz / 285Hz 音频，配文案"清理毒素""组织修复""爱的频率"。
- 40Hz gamma 有部分神经科学基础，但**临床证据远未确立**；
- 528Hz"爱的频率"、741Hz"净化"、285Hz"组织修复"**属于伪科学范畴**；
- 与八轴机制链同处一个产品，**整体拉低科学可信度**；FDA/MHRA 口径下**极易构成 claims 越界**。

## 六、提升方案

### P0（1–2 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| **P0-1** | **频率疗法降级**：移除疗效文案（"清理毒素""组织修复"），改为"放松/睡眠音频体验"；**从八轴机制链中剥离** | 无任何疗效宣称；不进入机制链 |
| P0-2 | **打卡极简化**：单次操作 ≤ 10 秒（如一键打卡 + 可选补充） | 有耗时埋点验证 |
| P0-3 | **与 M05 PGx 联动**：录入用药后自动生成基因型风险提示 | 见 M05 P0-1 |

### P1（3–6 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | **中断后重新激活路径**：断连 ≥ 3 天的用户回来时给"欢迎回来"而非惩罚 | 有明确的召回文案与激励 |
| P1-2 | 数据模型切换为 FHIR 资源名（MedicationRequest / MedicationStatement） | 导出符合 FHIR |
| P1-3 | 打卡反馈可视化：连续天数、趋势曲线、与八轴变化的关联 | 用户能看到"坚持 → 八轴改善"的因果可视化 |

### P2（2–4 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P2-1 | 依从率统计（PDC/MPR）并可导出给医生 | 有标准口径的依从指标 |
| P2-2 | 干预方案与因果推演闭环：实际轨迹 vs 反事实轨迹对比展示 | 用户能看到"如果没坚持会怎样" |
