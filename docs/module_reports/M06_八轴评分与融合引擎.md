## 二、流程走通性实测

**主链路**：输入 → `score_all_axes()` → 弱轴识别 → `fusion_engine.recommend()` → 建议

### 🔴 P0 级致命缺陷（上轮发现，本轮确认未修复）

| 缺陷 | 位置 | 后果 |
|---|---|---|
| **`_score_axis_H()` 签名未同步 `jurisdiction` 参数**，函数体内却引用该变量 | `axis_scorers.py:441` | 统一入口 `score_axis()` 传 3 个位置参数 → **每次调用必抛 `TypeError`** |
| **`fusion_engine.py:391` 用 `except Exception: axis_scores_block = {}` 静默吞掉** | `fusion_engine.py:391` | **前端不报错、API 不报错，缺陷完全不可见** |
| **E/G 轴共线** | `axis_scorers.py` | 两轴主输入同为 `hrv_rmssd`、阈值同为 30/20 → 仅 HRV 输入时输出逐点相同，**八轴实为七轴** |
| 参数外置未完成 | `axis_config.py` 已存在但接线未完成 | 阈值仍硬编码在 if-elif 中 |

**实测后果**（复现自上一轮，本轮确认）：
```
score_all_axes(biomarkers={...9 项}, wearable={...5 项})
  → 抛 TypeError
  → fusion_engine 静默吞掉
  → axis_scores = {}
  → weak_axes = []
```
**用户上传完整化验单，引擎输出与什么都没传完全一致。** 八轴可测量达成度是 **0%，不是"部分达成"**。

**修复成本**：约 2–5 行。

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| **失败可见性** | ❌ **最坏** | 静默降级让用户拿到"看起来正常但完全错误"的结果——这比报错更糟 |
| 结果可解释性 | ⚠️ | 八轴分数若不给"为什么是这个分"，用户无法信任 |
| 缺失输入的处理 | ⚠️ 待确认 | 用户只传了部分数据时，是否明确告知"哪些轴因数据不足未计算" |
| 输入成本 | ✅ 好 | 化验单 + 可穿戴是低门槛输入 |

**最需要改的一条**：**任何失败都必须 fail-loud**。融合引擎的静默 `except` 是当前最危险的单点。

## 四、市场与竞品对标

**需求判断**：真实但**已是红海**。2025–2026 资本高度集中。

| 竞品 | 定位 | 短板 |
|---|---|---|
| Function Health | 100+ 血液标志物 + AI 解读 | 分子轴强、可穿戴弱；无因果推演 |
| Neko Health | 全身扫描（累计融资 7 亿美元） | 无分子层，重资产 |
| Oura / WHOOP | 可穿戴日常评分 | 分子轴为零；Oura 2026 遭集体诉讼，指控睡眠分期"如抛硬币" |
| 美年健康"血液学时钟" | 2025-11 国内首款 AI 衰老评估 | 无干预闭环，无中医维度 |

**真正的空白**：不在"多轴打分"，而在**跨模态统一语义层 + 可解释归因**——现有玩家都只占一两个模态（Function 只有血液、Oura 只有穿戴）。**HealthLens 同时接入化验 + 穿戴 + 基因 + 中医，这个跨模态语义映射层是唯一护城河。**

## 五、可融合的开源技术

**检索结论：无现成"多轴融合"框架——这是真空白，别指望找轮子。**

### 🔴 关键判断：556 行 if-elif 打分器在 2026 年还有价值吗？

> **代码形态没有价值，知识资产有价值。**

理由：
1. if-elif **无法做敏感性分析**、**无法接入因果图**、**无法被审计**、**无法被非工程角色（中医专家）维护**；
2. 同样的逻辑用**声明式配置（YAML/DSL）+ 金标准测试集**表达，能被 LLM 生成、能被领域专家评审、能做回归测试。

**明确建议**：**删掉 if-elif 代码，把抽出的阈值与权重固化为数据文件 + 单元测试。**

⚠️ **例外（必须保留硬编码/规则表形态）**：确定性禁忌类规则——十八反十九畏、妊娠禁忌、危急值阈值。这类规则要的是**可证明的确定性**，不是灵活性。这部分属于 M08。

## 六、提升方案

### P0（1 周内，必须）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P0-1 | **修 `_score_axis_H()` 签名**（补 `jurisdiction` 参数） | `score_all_axes()` 不抛异常 |
| P0-2 | **删除 `fusion_engine.py:391` 的静默 `except`**，改 fail-loud + 结构化日志 + 监控告警 | 八轴失败必须可见、可告警 |
| P0-3 | **加端到端回归测试**：给定体检 9 项 + 可穿戴 5 项，断言 `weak_axes` 非空 | 测试守住"八轴必须产出"这条底线 |
| P0-4 | **E/G 轴解耦**（区分主输入或调整阈值） | 仅 HRV 输入时 E ≠ G |

### P1（3–6 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | **声明式重构**：if-elif → YAML/DSL 配置 + 加载器 | 中医专家可不改代码调整阈值 |
| P1-2 | 参数完全外置（`axis_config.py` 接线完成） | 代码中零硬编码阈值 |
| P1-3 | **金标准测试集**（≥ 50 组输入→期望轴分） | 每次权重变更跑回归并输出差异 |
| P1-4 | 可解释性输出：每轴给出"贡献指标 + 权重 + 缺失项" | 用户可见"为什么是这个分" |

### P2（2–4 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P2-1 | 数据不足时的**部分轴标记**（而非全部失效） | 明确告知"轴 C 因缺少 X 指标未计算" |
| P2-2 | 跨模态冲突消解（如可穿戴说睡得好、症状问卷说失眠） | 有明确的冲突处理策略并记录 |
