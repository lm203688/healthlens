## 二、本轮实测新发现（前几轮未识别）

### 🟢 N1｜因果推演模块已落地并跑通（好消息）
`app/lib/causal_simulator.py` + `app/api/causal.py` 已存在，头部注明 **S2-1（2026-10-13）**——即上一轮报告建议的因果化升级**次日就已实现**。

实测真跑：
```
causal_report(baseline, levers, weeks=8)
→ ['scm', 'counterfactual', 'calibration', 'sensitivity', 'not_clinical', 'disclaimer']
```
- `scm`：8 节点 + 结构边（含 coupling 系数与机制说明，如 `A→F` 0.12 "自噬-溶酶体选择性降解炎症小体组分"）
- 代码注释明确承认："耦合系数为透明启发式（文献锚定），**非因果识别量**；sensitivity 的诚实结论正是「须经前瞻队列标定」"
- fail-loud：输入越界返回 400，绝不静默降级

**评价**：科学态度诚实，是全项目最值得肯定的模块。**不再重复建议"从零建设"，改为接 DoWhy 做 refutation 严谨化。**

### 🔴 N2｜Google Health 是"可见但必失败"的死路
- `frontend/src/components/WearableDevices.jsx:7` 渲染了 `google_health`
- 但 `app/api/connections.py:31` 的 `ALLOWED_SOURCE_TYPES` **不含** `google_health`
- → 用户点击 → `connections.py:76` 校验失败 → **400**

修复：加 1 个字符串。

### 🔴 N3｜急救拦截了，但前端不说（安全关键）
- `check_emergency()` 实测**有效**：`胸痛`/`呼吸困难`/`心悸`/`胸痛 出汗` 均命中
- 中间件已全局注册（`app/__init__.py:121-122`）
- **但 `AgentChat.jsx` 完全没有 emergency 相关代码** → 用户看不到就医引导 = **拦截白做**
- 且 `胸口疼`/`我头晕`/`头疼` 未命中（词表偏书面语，口语漏检）

### 🟡 N4｜八轴打分器缺陷未修复（上轮 P0，本轮确认仍在）
`axis_scorers.py:441` `_score_axis_H()` 签名缺陷 → 100% 失效；`fusion_engine.py:391` 静默吞异常。**用户上传完整化验单，输出与什么都没传一样。**

## 四、跨板块的"开源替换 vs 自研"总裁决

### 直接用开源替换（**不要自研**）

| 能力 | 开源方案 | 许可 | 板块 |
|---|---|---|---|
| OCR 版面/表格 | **docling**（MIT，商用最干净）或 MinerU（协议需法务确认） | MIT | M02 |
| 生理信号处理 | **NeuroKit2** | MIT | M04 |
| 衰老时钟 | **pyaging** | MIT | M07 |
| 等位基因分型与 PGx 指南 | **pypgx** / **PharmCAT**（金标准，仅调用不受 MPL 传染） | MIT / MPL-2.0 | M05 |
| 因果估计与敏感性 | **DoWhy** | MIT | M07 |
| 中西药相互作用数据 | **DDInter 2.0** | 开放获取 | M08 |
| 中医基础 LLM | ShenNong-TCM-LLM / ChatMed-TCM 类（**不自训**） | — | M08 |
| PII / 临床实体识别 | **Presidio** / OpenMed | MIT / Apache-2.0 | M09 |
| FHIR 建模 | **fhir.resources** | — | M11 / M14 |
| DSAR 与数据地图 | **Fides** | Apache-2.0 | M13 |
| 防篡改审计 | **Trillian** | Apache-2.0 | M13 |
| 国际可穿戴连接器骨架 | **Open Wearables** | MIT | M03 |
| SEO 站框架 | **Astro** | MIT | M14 |

### 必须自研（**护城河**）

| 能力 | 理由 | 板块 |
|---|---|---|
| **多法域 claims 规则库** | 未见开源或 API 化对标（**但不可宣称"国际空白"**——Veeva/Klick/RegASK 存在，只是制药向） | M09 |
| **八轴跨模态语义映射层** | 现有竞品只占 1–2 个模态 | M06 |
| **8 轴 DAG 因果结构** | 工具给不了领域结构，这才是可解释性来源 | M07 |
| **GB/T 20348-2026 术语对齐** | 无开源可替，且是国标合规要求 | M08 / M04 |
| **禁忌规则表（十八反十九畏/妊娠禁忌/危急值）** | 这类规则要的是可证明的确定性，**不应改成模型** | M08 / M10 |
| **字段级 × 法域级同意模型** | 现成 CMP 无一支持此粒度 | M13 |
| **华为/小米/医院 LIS 适配器** | 开源无覆盖，且**审批资质本身是壁垒** | M03 |
| **MCP 业务语义层** | 对接的是自有能力 | M14 |
| 打卡/目标产品体验、积分裂变 | 强业务耦合 | M11 / M12 |

### 建议放弃 / 降级

| 对象 | 理由 |
|---|---|
| 频率疗法疗效宣称 | 伪科学范畴，拉低可信度，易触发 claims 越界 |
| ESP32 硬件作为产品主线 | C 端门槛致命；B 端被闭源器械占据且需器械证 |
| 自研甲基化时钟 | 前沿已转向蛋白组/器官时钟 |
| 自研中医大模型 | 直接用开源 + RAG |
| 自建主权云 | 直接买 |
| A2A 协议 | 医疗场景下多 agent 协商的审计与责任归属成本过高 |

## 五、三条跨板块的硬约束

1. **GB/T 20348-2026《中医基础理论术语》已于 2026-07-01 实施**（含舌象、脉象分标），证候与舌脉术语必须对齐——影响 M08、M04。
2. **Google Fit API 支持至 2026 年底终止**，须迁移 Health Connect——影响 M03。
3. **MCP 2026-07-28 第 5 版是 breaking change**（传输层无状态化），现有 Server 需改造——影响 M14。

## 六、一句话结论

> **合规层（M09/M13）与因果层（M07）已经是国际水准，核心算法层（M06）还是零。**
> 全项目最短的那块板是八轴打分器——它 100% 失效且被静默吞掉，而修复只需约 5 行代码。
> **先把最短的板补上，再把最强的板变成对外输出的产品。**
