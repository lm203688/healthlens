## 二、流程走通性实测

**主链路**：注册 → 登录 →（可选 TOTP）→ 完善档案 → 确定 jurisdiction → 进入业务

| 环节 | 状态 | 实测判据 |
|---|---|---|
| 注册 | ✅ 通 | `UserCreate` schema 存在 |
| 登录 | ⚠️ **schema 已改，调用点未全同步** | `LoginInput` 已改为 `account` 字段，但 `tests/conftest.py` 的 fixture 仍传 `email` → **测试套件 36 失败 / 293 通过 / 10 跳过**。补 1 行即降到 9 失败 |
| 验证码 | ✅ 通 | `verification_code.py` + 验证码服务 |
| TOTP | ✅ 通 | `totp_service.py` 存在且已接线 |
| 档案 | ✅ 通 | `profiles.py` 有 CRUD |
| jurisdiction 落库 | ✅ 通 | `User.jurisdiction` 存在，claims 引擎据此加载 YAML |

**结论**：业务链路是通的，**但"改 schema 不同步调用点"这个模式本身就是风险信号**——它说明没有契约测试守住接口边界。M06 的 H 轴签名缺陷是同一个模式的又一次发作。

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| 账号形式 | ✅ 好 | 用 `account` 统一邮箱/手机号，符合中国用户习惯 |
| 密码强度 | ✅ 好 | 要求 `TestPassword123!` 级复杂度 |
| 多因子 | ✅ 好 | TOTP 已支持 |
| **法域确定方式** | ❌ **不符合习惯** | 法域是**法律概念**，普通用户不知道自己属于 `us_fda` 还是 `eu_mdr`。让用户自己选，等于让用户承担合规判断责任 |
| 账号注销 | ⚠️ 待确认 | 注销入口与 GDPR 删除请求（M13）是否联动，未见明确接线 |

**最需要改的一条**：法域应该**自动推断**（手机号国家码 / IP 归属 / 支付币种），结果展示为"根据您所在地区，我们已按 XX 规范提供内容"，并允许高级用户手动覆盖。这是把合规负担从用户转移到系统的关键设计。

## 四、市场与竞品对标

| 对象 | 定位 | 开源 | 说明 |
|---|---|---|---|
| Auth0 / Clerk | 商业身份云 | 否 | 能力强，但数据出境与主权要求下不宜用于健康数据 |
| Supabase Auth | 开源托管 | 是 | 生态好，法域驻留需自行部署 |
| Logto | 国产开源身份方案 | 是 | 中文支持与私有化友好 |
| Casdoor | 国产开源 IAM | Apache-2.0 | 私有化场景常见 |

**市场判断**：认证是**完全商品化的能力**，自研没有战略价值。HealthLens 自研的合理理由只有一个——**`jurisdiction` 与 claims 引擎的深度耦合**，这是通用身份产品不会提供的。

## 五、可融合的开源技术

| 项目 | 许可 | 活跃度 | 能解决什么 | 集成成本 | 建议 |
|---|---|---|---|---|---|
| Logto / Casdoor | Apache-2.0 系 | 活跃 | 替代自研认证主体 | 中 | **可选**：若团队想减负可替换，但保留 jurisdiction 扩展字段 |
| `py_webauthn` | BSD | 活跃 | Passkey / WebAuthn 无密码登录 | 低 | **建议引入**：健康类应用密码流失率高，passkey 显著降低登录摩擦 |
| `pwdlib` / `argon2-cffi` | MIT / Apache | 活跃 | 密码哈希（Argon2id） | 低 | 确认当前哈希算法，若非 Argon2id 应升级 |

> ⚠️ 上表活跃度来自检索，**具体版本号未逐项核实**，引入前请再确认。

## 六、提升方案

### P0（1 周内，必须）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P0-1 | 修 `tests/conftest.py`：fixture 补 `account` 字段 | 测试失败 36 → 9 |
| P0-2 | 加**接口契约测试**：所有 auth 相关 schema 变更必须触发测试 | schema 改动未同步 → CI 必红 |
| P0-3 | 确认密码哈希算法为 Argon2id（或 bcrypt cost ≥ 12） | 审计报告有明确结论 |

### P1（2–4 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | **法域自动推断**：手机号国家码 → IP 归属 → 支付币种，逐级 fallback | 新用户无需手动选择法域；可手动覆盖并有审计留痕 |
| P1-2 | 账号注销与 GDPR 删除请求联动 | 注销即触发 M13 的数据删除流程与留痕 |
| P1-3 | 登录失败限流与异常登录告警 | 有速率限制；异常地理登录触发通知 |

### P2（1–2 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P2-1 | 引入 Passkey / WebAuthn | 支持无密码登录 |
| P2-2 | 会话管理可视化（设备列表、强制下线） | 用户可查看并终止会话 |
