## 二、流程走通性实测

| 环节        | 状态       | 判据                                                                                  |
| --------- | -------- | ----------------------------------------------------------------------------------- |
| MCP RPC   | ✅ 通      | 三大方法齐备 + `_check_auth_for_method()` 鉴权 + `_is_notification()` 处理                    |
| MCP 工具浏览器 | ✅ **亮点** | `GET /tools` 提供可视化浏览                                                                |
| FHIR 导出   | ✅ 通      | Patient + Observation + DiagnosticReport Bundle，含 `v3-ObservationInterpretation` 编码 |
| 知识推荐      | ✅ 通      | 食疗 / 非药物 / 养生方案三类                                                                   |
| SEO 生成    | ✅ 通      | 页面生成 + 发布 + 关键词集群管理（管理员端点）                                                          |
| **古籍原文**  | ❌ **无**  | 701 条仅**书目元数据**（书名/作者/朝代/类目/源文件），**无原文切片与八轴标注**                                     |

**结论**：开放生态（MCP + FHIR）**做得意外地好**——MCP 三大方法 + 鉴权 + 工具浏览器，FHIR 用标准编码。这在独立项目中属上乘。

## 三、是否符合人类使用习惯

| 维度             | 评价        | 说明                                                                                         |
| -------------- | --------- | ------------------------------------------------------------------------------------------ |
| 知识库可检索性        | ⚠️        | 701 条书目若无原文，用户只能看到书名，**价值极低**                                                              |
| MCP 工具可发现性     | ✅ 好       | 有 `/tools` 浏览器                                                                             |
| **SEO 页面质量风险** | ❌ **高风险** | 批量生成 SEO 页面（`pages/generate` + `pages/publish`）若质量低，**会伤害品牌与搜索排名**（Google 对大规模生成内容有明确惩罚机制） |
| 分享与外链          | ✅ 通       | 与 M09 分享链路联动                                                                               |

**最需要改的一条**：**SEO 批量生成必须有质量闸门**。健康领域属 YMYL（Your Money or Your Life），Google 对此类内容的 E-E-A-T 要求最高——低质批量页在这个领域是负资产，不是流量入口。

## 四、市场与竞品对标

| 对象                       | 定位                                                                  | 说明                                                                                             |
| ------------------------ | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **MCP**                  | Anthropic 2024-11 提出，现由 Agentic AI 基金会管理                            | **2026-07-28 第 5 版主规范**：移除协议级会话（传输层无状态）、Extensions 成为一等公民，**含 breaking changes，现有 Server 需改造** |
| **A2A**                  | Google 2025-04-09 推出，捐赠 Linux Foundation（AAIF），**v1.0（2026-03-12）** | 定位 Agent 间协调，**不替代 MCP**。2026-06-25 出现 MCP+A2A 融合草案                                            |
| **wso2/fhir-mcp-server** | Apache-2.0                                                          | 可直接把 FHIR Server 暴露为 MCP                                                                       |
| **国家中医药古籍数字图书馆**         | 2025-05-10 体验版上线（八大馆）                                               | **非开源**，可作权威底本                                                                                 |
| 中医开源模型                   | ShenNong-TCM-LLM、ChatMed-TCM 等                                      | 多为研究与 demo 级，成熟度中低                                                                             |
| Astro vs Next.js         | 静态站框架                                                               | **Astro 默认零 JS、纯静态，2026 多篇评测在 SEO/CWV 维度占优**                                                   |

## 五、可融合的开源技术

| 项目                       | 许可         | 活跃度            | 能解决什么                 | 建议                              |
| ------------------------ | ---------- | -------------- | --------------------- | ------------------------------- |
| **MCP 第 5 版规范**          | 开放规范       | 2026-07-28     | 工具/数据接入标准             | **必须跟进无状态化改造**（breaking change） |
| **fhir.resources**       | —          | 活跃             | pydantic v2 的 FHIR 模型 | **替换自研 FHIR 模型**                |
| **wso2/fhir-mcp-server** | Apache-2.0 | —              | FHIR Server → MCP     | 参考实现                            |
| **Astro**                | MIT        | 活跃             | 零 JS 静态站，SEO/CWV 优    | **SEO 站用 Astro，与主应用分离**         |
| Awesome-TCM-LLM          | MIT        | 121★ / 2026-10 | 中医 LLM/数据集索引          | 当目录用                            |

**取舍**：

- **MCP Server：自研业务语义层**，但紧跟 2026-07-28 无状态改造。
- **FHIR 导出：直接用 `fhir.resources`，别自研模型。**
- **古籍语料只做检索增强，不自研中医大模型**。
- **SEO 站用 Astro，内容站与主应用分离。**

## 六、提升方案

### P0（1–2 周）

| 项        | 动作                                             | 验收标准                             |
| -------- | ---------------------------------------------- | -------------------------------- |
| **P0-1** | **SEO 批量生成加质量闸门**：生成后必须人工/规则审核才发布；健康类内容需有可追溯来源 | 未审核页面不可 publish                  |
| **P0-2** | **MCP 无状态化改造**（对齐 2026-07-28 第 5 版）            | 不依赖协议级会话；有 breaking change 的兼容测试 |
| P0-3     | FHIR 模型切到 `fhir.resources`                     | 导出通过 FHIR 校验器                    |

### P1（3–6 周）

| 项    | 动作                                       | 验收标准                      |
| ---- | ---------------------------------------- | ------------------------- |
| P1-1 | 古籍从"701 条书目"推进到"原文切片 + 八轴标注"（首批 ≥ 100 条） | 可检索到原文而非仅书名               |
| P1-2 | MCP 工具集扩展：暴露八轴评分、时钟、中医安全层                | 外部 Agent 可调用（对齐 M10 P2-1） |
| P1-3 | SEO 站迁移到 Astro，与主应用分离                    | 主应用不受 SEO 站发布影响           |

### P2（2–4 月）

| 项    | 动作                                                  | 验收标准        |
| ---- | --------------------------------------------------- | ----------- |
| P2-1 | 古籍原文检索增强（接开源中医 LLM 做解读，**不自训**）                     | 回答附原文出处     |
| P2-2 | 对外发布"Powered by HealthLens"能力清单（MCP 工具 + claims 过滤） | 有对外文档与 demo |
