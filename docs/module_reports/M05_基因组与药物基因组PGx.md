## 二、流程走通性实测

**主链路**：上传基因数据 → 基因型判读 → 星型等位基因推断 → CPIC 指南匹配 → 用药建议 + 安全提示

| 环节 | 状态 | 判据 |
|---|---|---|
| 指南覆盖 | ✅ 好 | 已实现 **CYP2D6 / CYP2C19 / DPYD / SLCO1B1** 四基因，均为 CPIC A/B 级证据 |
| 本地解读 | ✅ 通 | `interpret_genotype()`，注释明确对齐 CPIC（CYP2D6 AS 0.6–1.0 判 IM、1.1–3.0 判 NM） |
| 实时富集 | ✅ 通 | `analyze_user_genome_enriched()` 叠加实时 CPIC 等级（Phase 2） |
| 外部 API | ✅ 好 | 对接 **ClinPGx**（api.clinpgx.org，PharmGKB 继任，Stanford/NIH，无密钥，CC BY-SA 4.0）+ **CPIC PostgREST**（含 cpiclevel A/B/C/D） |
| 依赖洁癖 | ✅ **优秀** | 仅标准库（urllib + asyncio + json + time），**零第三方依赖** |
| 缓存与限流 | ✅ 好 | 有 `_ratelimit()` 与本地缓存 |
| 诚实标记 | ✅ **优秀** | 注释：`# S0-3（2026-10-12）：仅在实际获得 CPIC 等级时才标记 guidelines_attached` —— 拿不到就不假装拿到了 |

**结论**：**这是全项目工程质量最高的板块之一。** 有权威指南背书、有实时富集、有 fail-loud 的诚实设计、零依赖。国际竞品中少见。

**唯一缺口**：未见**中西药相互作用**层（整合医学的关键差异化点，见 M08）。

## 三、是否符合人类使用习惯

| 维度 | 评价 | 说明 |
|---|---|---|
| 报告可读性 | ⚠️ 待确认 | "CYP2D6 *1/*4 中间代谢型"对普通用户不可读，需翻译为"您对某类药物代谢偏慢，医生可能需要调整剂量" |
| **遗传咨询提示** | ❌ **未见** | DTC 基因报告涉及 incidental finding（意外发现），应有明确的"建议咨询遗传咨询师/医师"提示 |
| 数据敏感度提示 | ⚠️ 待确认 | 基因数据是不可撤销的敏感数据，上传前应有明确的不可逆性告知 |
| 与用药的联动 | ⚠️ 待确认 | 是否自动关联用户正在服用的药物（M11 有 medications 模块）→ 这是 PGx 最大价值点 |

**最需要改的一条**：PGx 的价值不在"告诉用户基因型"，而在"**告诉用户正在吃的药是否有基因型风险**"。若未与 M11 的用药清单联动，这个板块的价值损失 80%。

## 四、市场与竞品对标

**需求判断**：**真实、有支付方、增长确定**。
GM Insights（2026-07）预计 2026 年全球 PGx 市场约 **62 亿美元**，且已从"单项目检测"转为医疗系统基础设施投资。

| 竞品 / 参考 | 定位 | 开源 | 说明 |
|---|---|---|---|
| OneOme / GeneSight | 商业 PGx 检测 | 否 | 有支付方，临床渠道强 |
| 23andMe | DTC 基因 + 健康报告 | 否 | 遭遇重大数据泄露与监管压力 |
| Color / Invitae | 临床基因检测 | 否 | 医疗系统侧 |
| **PharmCAT** | VCF → 星型等位基因 → CPIC 建议 | **MPL-2.0** | **事实标准**，v3.4.0（2026-07-14） |
| **pypgx** | Python 全栈 PGx | **MIT** | v0.27.0（2026-06-12） |

**痛点**：是"准不准 + 是否遵循权威指南"——**这正是本板块已做对的部分**。

## 五、可融合的开源技术

| 项目 | 许可 | 活跃度 | 能解决什么 | 集成成本 | 建议 |
|---|---|---|---|---|---|
| **pypgx** | MIT | 98★ / v0.27.0（2026-06） | 星型等位基因 calling + PharmVar/CPIC/DPWG | 低 | **建议引入**：与 FastAPI 同栈，MIT 商用干净 |
| **PharmCAT** | MPL-2.0 | 195★ / v3.4.0（2026-07） | 权威可追溯的金标准 | 中（Java，需容器化） | **建议作交叉校验**；仅调用不受 MPL 传染 |
| **cpic-data** | NOASSERTION | 34★ / 2026-10 | CPIC 官方机器可读指南数据 | 低 | **定时同步**，替代手工维护 |
| **ClinPGx API** | — | 2025 起 PharmGKB 更名整合 | 统一 ClinPGx/CPIC/PharmCAT 知识库 | 低 | **已在用，保留** |

**取舍**：
- **不要自研任何等位基因分型或指南规则**——这是有权威标准的成熟领域，自研即风险。
- **必须自研**：① 报告可读化与患者沟通；② **中西药相互作用注释**（整合医学差异化点，开源无覆盖）；③ 多法域合规文案（不同辖区对 DTC 基因报告措辞要求不同）；④ 与八轴表征的关联层。

## 六、提升方案

### P0（1–2 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P0-1 | **与 M11 用药清单联动**：扫描用户在用药物 × 基因型 → 主动风险提示 | 用户录入药物后自动生成 PGx 风险卡 |
| P0-2 | 报告可读化层：基因型 → 患者可理解表述 + 医生可操作表述（双版本） | 非专业用户可读懂主要结论 |
| P0-3 | 遗传咨询提示 + 数据不可逆性告知 | 上传前明确提示 |

### P1（3–6 周）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P1-1 | 引入 pypgx 扩展基因覆盖 | 覆盖基因数 ≥ 10（当前 4） |
| P1-2 | 以 PharmCAT 做交叉校验 | 对同一 VCF，两者结论一致率有量化结果 |
| P1-3 | CPIC 指南数据定时同步 | 指南更新后 X 天内自动同步并留痕 |

### P2（2–3 月）

| 项 | 动作 | 验收标准 |
|---|---|---|
| P2-1 | 中西药相互作用层（与 M08 `tcm_safety` 打通） | 服用中药 + 西药时能提示相互作用 |
| P2-2 | 多法域合规文案（对齐 M09 claims 引擎 5 法域） | 各法域输出符合当地 DTC 基因报告要求 |
