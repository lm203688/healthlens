# HealthLens 前瞻队列研究数据治理计划（v0.1-draft）

**版本**：v0.1.0-draft · 2026-10-18
**规范对齐**：GDPR + 中国《个人信息保护法》（PIPL）+ FAIR 数据原则
**研究标题**：HealthLens 整合医学 n-of-1 前瞻队列研究方案（2026-2027）

## 0. 计划目的

本文件是 HealthLens 前瞻队列研究的**数据治理计划**，明确：

- 数据分类与采集范围
- 数据去标识化流程
- 数据存储与访问控制
- 数据共享与使用限制
- 数据删除与生命周期
- 数据合规框架

**诚实声明**：本计划目前**尚未**获得任何 IRB 批准，仅作为提交材料供伦理委员会审阅。

## 1. 数据分类

### 1.1 数据分类矩阵

| 数据类型 | 具体内容 | 是否采集 | 合规依据 |
|---|---|---|---|
| **PII**（个人身份信息） | 姓名、邮箱、电话、IP 地址 | ❌ 不采集 | GDPR Art. 5.1(c) 最小必要 |
| **PHI**（健康信息） | 睡眠、活动、心率、血糖 | ⚠️ 去标识化后采集 | PIPL §28 敏感个人信息 |
| **人口学数据** | 年龄、性别、地域 | ⚠️ 聚合后采集 | GDPR Art. 4.1 |
| **研究数据** | HealthLens 计算的 wellness 指标 | ⚠️ 仅研究用途 | GDPR Art. 6.1(f) 合法利益 |
| **元数据** | 设备型号、OS 版本 | ⚠️ 聚合后采集 | GDPR Art. 5.1(b) 目的限制 |

### 1.2 数据字典

## 2. 数据采集

### 2.1 采集原则

- **最小必要**：仅采集研究必需的最小数据量
- **知情同意**：采集前获得参与者书面同意
- **自愿性**：参与者可随时退出，数据可删除
- **安全性**：采集过程使用加密传输（TLS 1.3）

### 2.2 采集来源

1. **参与者主动上报**：
   - 健康应用数据（Fitbit、Apple Health 聚合摘要）
   - 参与者自报告的健康指标（睡眠、活动等）
2. **平台 telemetry**（去标识化）：
   - HealthLens 计算的健康指标（睡眠轴、代谢轴等）
   - 参与者与平台的交互记录（仅元数据，不含内容）

### 2.3 采集频率

| 数据类型 | 采集频率 | 采集方式 |
|---|---|---|
| 健康指标（睡眠、活动等） | 每日 1 次 | 参与者主动上报或自动同步 |
| 平台 wellness 指标 | 实时（去标识化聚合） | 平台 telemetry |
| 自报告问卷 | 每周 1 次 | 参与者填写电子问卷 |
| 元数据 | 实时 | 平台自动记录 |

## 3. 数据去标识化

### 3.1 去标识化流程

```
原始数据 → 移除直接标识符 → 应用 k-anonymity → 稳定 hash 替换 ID → 去标识化数据
```

### 3.2 直接标识符移除

移除以下字段：

- 姓名、邮箱、电话
- IP 地址、设备 MAC 地址
- 地理位置精确坐标（保留城市级）
- 照片、视频、录音
- 任何可识别个人的信息

### 3.3 k-anonymity 应用

- **k 值**：k ≥ 5（每个匿名组至少 5 个个体）
- **应用范围**：所有人口学数据与元数据
- **验证方法**：统计每个匿名组的个体数量

### 3.4 稳定 hash 替换

- **算法**：SHA-256（单向 hash）
- **盐值**：研究专属盐值，不公开
- **目的**：用 hash 值替换原始 ID，保留数据关联但不可逆

### 3.5 去标识化验证

- **人工审查**：抽样 5% 的数据，人工检查去标识化效果
- **自动化测试**：使用去标识化测试工具验证
- **审计日志**：所有去标识化操作记录到不可篡改日志

## 4. 数据存储

### 4.1 存储架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        数据存储架构                              │
├─────────────────────────────────────────────────────────────────┤
│  原始数据层（加密）                                               │
│  ├─ AES-256-GCM 加密                                            │
│  ├─ 访问日志审计                                                 │
│  └─ 仅研究团队访问                                               │
│                                                                 │
│  去标识化数据层                                                   │
│  ├─ 去标识化完成                                                 │
│  ├─ 仅限研究用途                                                 │
│  └─ 合作研究者可申请访问                                         │
│                                                                 │
│  聚合数据层                                                       │
│  ├─ k-anonymity 聚合                                             │
│  ├─ 公开发布（预印本）                                           │
│  └─ 无需申请即可访问                                             │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 加密存储

- **算法**：AES-256-GCM
- **密钥管理**：HSM（硬件安全模块）托管
- **密钥轮换**：每季度轮换一次
- **备份**：加密备份，异地存储

### 4.3 访问控制

- **最小权限原则**：仅研究团队成员有访问权限
- **多因素认证**：所有访问需 MFA
- **IP 白名单**：仅限指定 IP 访问
- **审计日志**：所有访问操作记录到不可篡改日志

## 5. 数据传输

### 5.1 传输加密

- **协议**：TLS 1.3
- **证书固定**：客户端固定服务器证书，防止中间人攻击
- **密钥交换**：ECDHE（临时密钥交换）
- **加密套件**：TLS_AES_256_GCM_SHA384（仅启用 AEAD）

### 5.2 传输审计

- **传输日志**：记录所有数据传输操作
- **异常检测**：异常数据传输触发告警
- **传输监控**：实时监控数据传输流量

## 6. 数据共享

### 6.1 数据共享原则

- **仅研究用途**：数据仅用于本研究，不用于商业目的
- **去标识化**：所有共享数据已完成去标识化
- **数据契约**：所有数据共享需签署数据契约
- **可追溯**：所有数据共享操作记录到审计日志

### 6.2 数据共享范围

| 数据类型 | 共享对象 | 共享条件 |
|---|---|---|
| 原始数据 | IRB 批准后合作研究者 | 签署数据契约 + IRB 批准 |
| 去标识化数据 | 合作研究者 | 签署数据契约 |
| 聚合数据 | 公开（预印本） | 无需申请 |

### 6.3 数据契约

数据契约包含：

- **使用范围**：仅限本研究，不转让、不出售
- **保护义务**：接收方承担同等数据保护义务
- **删除义务**：研究结束后删除所有数据副本
- **审计义务**：接收方接受定期审计
- **违规责任**：违反数据契约需承担法律责任

## 7. 数据删除与生命周期

### 7.1 数据生命周期

```
采集 → 去标识化 → 存储 → 分析 → 归档 → 删除
  ↑                                      │
  └──────────── 参与者申请删除 ───────────┘
```

### 7.2 删除流程

1. **参与者申请**：参与者提交数据删除申请
2. **验证身份**：验证申请者身份（去标识化后仍需验证）
3. **删除执行**：30 天内完成所有数据副本删除
4. **删除确认**：向参与者发送删除确认通知
5. **审计日志**：删除操作记录到不可篡改日志

### 7.3 数据保留期限

| 数据类型 | 保留期限 | 删除方式 |
|---|---|---|
| 原始数据 | 研究结束后 5 年 | 安全删除（覆盖 3 次） |
| 去标识化数据 | 研究结束后 5 年 | 安全删除 |
| 聚合数据 | 永久（或 10 年） | 无需删除 |
| 审计日志 | 5 年 | 安全删除 |

## 10. 数据保护评估（DPIA）

### 10.1 DPIA 必要性

本研究涉及大规模处理健康信息，需进行数据保护影响评估（DPIA）。

### 10.2 DPIA 内容

- **系统描述**：系统架构与数据流
- **数据流分析**：所有数据处理操作
- **风险识别**：所有潜在数据风险
- **缓解措施**：所有缓解措施与有效性
- **残余风险**：剩余风险评估

### 10.3 DPIA 报告

DPIA 报告将作为 IRB 提交的附件，见 `docs/prospective_cohort/dpia_report.md`（占位）。
