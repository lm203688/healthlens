## 1. G1 数据合规框架（GDPR/健康数据）

### 1.1 当前状态（已有）
- **GDPR API**（`app/api/gdpr.py`）：Article 15 导出 / Article 17 删除 / Article 13-14 同意记录 / Article 35 DPIA / 权利清单（rights）/ 字段级同意（field-consent）。
- **字段级×法域级同意模型**（`app/models/field_consent.py`）：(user, field, jurisdiction, purpose) 四维同意，支持 GDPR Art.7「具体/知情/明确」。
- **区域数据驻留代码级约束**（`app/lib/region_guard.py`）：PII 跨 region 边界读写→立即抛异常；基因数据（HGRAC 中国遗传资源不得出境）、诊断结果、健康观察、GDPR 端点已接入。
- **5 法域 Claims Policy**（claims_policy/）：CN 32 + US 26 + UK 20 + EU 24 + AU 5 banned_terms，fail-closed 拦截 21 端点。
- **数据脱敏**（`app/core/desensitize.py`）：mask/pseudonymize/anonymize 三级。

### 1.2 缺口（缺什么）
- **健康数据专项合规**：GDPR 是 EU 法域，**中国健康医疗数据合规**（《个人信息保护法》PIPL + 《人类遗传资源管理条例》HGRAC + 《数据安全法》）未成体系文档。
- **知情同意全链路**：当前同意记录有 API + 模型，但**用户旅程中的知情同意展示/撤回流程**未文档化（何时收集、展示什么、如何撤回）。
- **数据使用许可**：数据接入（外部数据源如队列/合作方）的**使用许可条款**未定义（谁提供、授权范围、用途限制）。

### 1.3 依赖
- 合规专家（中国数据合规专项 + PIPL/HGRAC 解读）
- 法务（知情同意文本审查）

### 1.4 路径（可执行）
1. **P0**：建立 `docs/compliance/data_compliance.md`——中国健康数据合规专项（PIPL 核心条款映射 + HGRAC 基因数据出境 + 数据安全法分级）。
2. **P0**：知情同意全链路文档化（注册→采集→使用→撤回，每环节同意点+展示文本）。
3. **P1**：数据使用许可模板（外部数据源接入的先决条件——来源许可/用途限制/期限）。

## 2. G2 持牌终审事实化

### 2.1 当前状态（已有）
- **诊断门控**（`app/core/diagnosis_gate.py`）：默认 `inactive`（active=False），激活前 `diagnose()` fail-closed 返回 `not_active`，**不执行任何诊断逻辑**；激活开关 `HEALTHLENS_DIAGNOSIS_GATE`。
- **语义声明**：任何诊断结论须由**持牌医疗机构**出具（门控层内部语义）。
- **复核端点**（`app/api/diagnosis.py::review_diagnosis`，PUT /results/{id}）：`require_doctor_or_admin`（doctor/admin 角色），状态流转 confirmed/rejected/modified，记录 `reviewed_by`。

### 2.2 缺口（缺什么）
- **终审流程代码级强制**：当前 `review_diagnosis` 是**医生复核端点**，但**门控未激活时无强制终审路径**（即：即使未来激活，终审是 API 端点而非门控内强制语义）。
- **终审流程文档化**：无独立文档说明"AI 辅助评估 → 持牌医师终审 → 结论出具"的完整流程与责任边界。

### 2.3 依赖
- 合规专家（终审流程与监管要求对齐）
- 持牌医师（终审实际操作者）

### 2.4 路径（可执行）
1. **P0**：建立 `docs/compliance/physician_final_review.md`——终审流程文档（AI 辅助评估→持牌医师复核→结论出具；状态流转 pending→confirmed/rejected/modified；责任边界：AI 不终审、医师终审）。
2. **P1**：门控激活时的**终审强制语义**设计（diagnose() 激活后仍应由持牌机构校验——当前已有语义声明，需落地为流程文档+代码注释）。
3. **诚实边界**：不宣称"已实现持牌终审系统"——终审是**流程设计 + API 端点**，**持牌机构接入/认证**是外部事项（未完成）。

## 3. G3 医疗器械分类评估

### 3.1 当前状态（已有）
- **定位声明分水岭**（`docs/HEALTHLENS_POSITIONING_REFACTOR_2026-11-04.md` §2）：是否激活诊断门控 = 是否进入"医疗器械"监管路径，**本平台默认不进入**。
- **PRS gate 前置**（`app/core/prs_framework.py`）：基因/化验数据接入前先做医疗器械分类评估 + 基因数据合规路径评估；gate 未过返回 gate_pending。

### 3.2 缺口（缺什么）
- **MDR/FDA 分类自评文档**：未做**当前产品的医疗器械分类自评**（属哪类？MDR Class I/IIa/IIb/III？FDA Class I/II/III？需否注册/豁免？）。

### 3.3 依赖
- 合规专家（MDR/FDA 分类规则解读）
- 监管路径评估（外部：如拟上市，需咨询监管顾问）

### 3.4 路径（可执行）
1. **P1**：建立 `docs/compliance/medical_device_classification.md`——MDR/FDA 分类自评（当前产品=健康评估工具，**非诊断**，应属**非医疗器械**或低风险类；若激活诊断门控则升级为医疗器械——自评明确当前默认状态）。
2. **诚实边界**：自评是**初步评估**，不构成监管意见；若拟激活诊断门控/上市，需**正式监管咨询**（外部事项）。
