### 核心结论（复用价值最高的事实，后续不要再重复取证）
- **八轴只有 1 轴能算**：`data/healthlens_config.json` 定义 A–H 八轴，但只有 `bioage_engine`
  的第 9 轴（代谢-炎症）有打分器；`fusion_engine.py:334` 的 `weak_axes` 完全由调用方传入。
  体检指标只能映射到 F、A 两轴，B/C/D/E/G/H 无数据来源。
- **L1→L5 不是链**：`diagnosis_agent.py:236-242` 中 L1(ClinVar)、L2(UniProt，不消费 L1 输出)、
  L3(KEGG，依赖用户自带 uniprot_id，否则写死 score=50/unknown)、L4/L5 交给 LLM；
  而 `.env` 无任何 LLM 凭证 → LLM 必然 `ValueError`，实际跑的是规则引擎。
- **宣称-实现落差**：README 说"701 部古籍语料库"，实际是 701 条书目元数据，全文仅 2 部。
  论文写十轴(A–J)，代码只有八轴(A–H)。
- **测试门禁被架空**：`ci.yml` `BASELINE=31`（31 个失败测试视为正常），ruff `continue-on-error`，mypy `|| true`。
- **OCR 会伪造数据**：`ocr_engine.py:43` 缺依赖时静默返回固定"血糖 6.8/胆固醇 5.8"。医疗级隐患。
- **Upload.jsx 整页不可用**：`fileInputRef` 声明后从未赋值 `.current`，点击无反应。
- **连接器全 mock**：`.configure()` 全仓零调用点 → OAuth 从未跑通过。
- **四角色 Agent 无 LLM**：`healthlens_agent/` 全目录无 LLM 客户端调用，是关键词字典 + 单向管道。
  Critic 判 REVISE 后不回灌 Executor。Benchmark 七维度分数是硬编码常量 `70,45,35,65,55,75,60`。
- **MCP 是最扎实的真资产**：真 JSON-RPC 2.0，10 个工具三层分级，双路径（官方 mcp 包 + 降级自研 stdio）。
- **部署在线**：healthlens.cc 200 / api.healthlens.cc 200 (v0.22.0)；但 growth.py:46 硬编码的
  `healthlens.app` 实测不可达 → 分享链接全失效。
- **版本漂移**：pyproject 0.8.2 / config.py 0.22.0 / server.json 0.3.0 / README 0.9.0 / PRINCIPLES 0.16.0。
