# HealthLens 联邦学习 + 区域数据驻留架构方案（S4）

> 目标：把「跨境多中心协作 + 区域数据驻留 + 联邦学习」三条线合并为
> 一套架构，解决 L2 国际化阶段的隐私合规与数据协作双重需求。
>
> **状态**：架构设计完成；实现需 3-6 个月工程 + 外部合作方。

## 1. 问题陈述

当前项目已有：
- **region_guard**：请求级区域驻留强制（用户/记录必须同区域）
- **五法域 claims policy**：CN/US/UK/EU/AU 差异化输出过滤
- **S2-2 n-of-1 数据层**：`data_residency_region` 分区键

**未有**：
- 跨境数据协作机制（EU/US 用户数据不能出境到 CN 服务器）
- 多中心联合学习（隐私保护下的模型联合训练）
- 差分隐私预算分配

## 3. 三层架构

### 3.1 数据驻留层（现有）

- **区域划分**：CN / US / EU / UK / AU（与 claims policy 法域对齐）
- **本地存储**：每区域独立 PostgreSQL 集群
- **本地计算**：每节点运行本地模型，原始数据不出区
- **region_guard**：读写端点强制用户/记录同区域

### 3.2 隐私预算层（新增）

**差分隐私（DP）预算分配**：

| 参数              | 全局预算 ε   | 每轮预算  | 说明                       |
| ----------------- | ------------ | --------- | -------------------------- |
| 八轴阈值校准      | ε = 1.0      | ε/100     | 100 轮联合训练             |
| 因果耦合系数      | ε = 0.5      | ε/50      | 50 轮（更敏感）            |
| 术语映射权重      | ε = 0.3      | ε/30      | 30 轮（跨域敏感）          |
| **总预算上限**    | **ε ≤ 5.0**  |           | 累积不超该阈值             |

**实现**：
- 每节点本地执行 DP-SGD（Differential Privacy via Stochastic Gradient
  Descent）
- 使用 TensorFlow Privacy 库或 Opacus（PyTorch）
- 每轮本地梯度加高斯噪声（σ 由预算和训练步数推导）

**预算监控**：
- 独立 `DPBudgetMonitor` 表记录每轮消耗
- 累积 ε 超阈值 → 冻结联合训练，等待新协议

### 3.3 模型协作层（新增）

**技术选型对比**：

| 方案           | 优势                       | 劣势                       | 推荐？    |
| -------------- | -------------------------- | -------------------------- | --------- |
| 横向联邦（HF） | 每节点独立数据             | 通信开销大                 | ✅ 首选    |
| 纵向联邦（VF） | 数据互补                   | 需 ID 对齐，隐私风险高     | ❌ 谨慎    |
| 联邦蒸馏       | 通信量小                   | 需中心教师模型             | ⚠️ 备选    |
| 边缘学习       | 通信量最小                 | 硬件要求高                 | ⚠️ 未来    |

**推荐**：横向联邦 + 差分隐私 + TEE 加密聚合。

**协作协议**：
```
Round 1..N:
  1. Aggregator 广播当前全局模型版本 v_t
  2. 每节点本地训练 step，得到梯度 g_i（已加 DP 噪声）
  3. 节点把 g_i 加密上传到 Aggregator
  4. Aggregator 安全聚合 Σ g_i / |nodes|（P2P TEE）
  5. Aggregator 更新全局模型 v_{t+1} = v_t + α * Σ g_i / |nodes|
  6. 广播 v_{t+1}
```

**TEE 方案**：
- Intel SGX / AMD SEV-SNP（x86 服务器）
- ARM TrustZone（Raspberry Pi 边缘节点）
- 或软件方案：MPC（多方计算）+ secret sharing

### 4.3 claims policy 联动

跨境联邦协作下，输出结果需**同时满足**：
- 用户法域的 claims policy
- 联邦协议中的跨境限制（若联邦协议更严，采用更严规则）

```python
def federated_output_filter(output, user_jurisdiction, federation_policy):
    strictest = max(user_policy, federation_policy)
    return apply_filter(output, strictest)
```

## 5. 隐私预算分配的公平性

**问题**：小节点（如 AU）贡献数据少，但共享全局模型收益。大节点（如 CN）
贡献多，但 DP 噪声更大，模型质量下降。

**解决方案**：
- **加权贡献**：贡献大的节点在聚合权重中占更大比例
- **贡献审计**：每个节点的贡献量记录在 `ContributionLedger` 表
- **贡献积分**：贡献可兑换高级 API 额度或联合署名机会
