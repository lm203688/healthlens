# HealthLens GraphRAG 古籍评估报告（S2-5）

> 目标：评估将 613 条古籍切片升级为知识图谱 + GraphRAG 的成本、收益、
> 替代路线，为 S2 阶段的技术选型提供决策依据。
>
> **决策摘要**：**推迟到 S4 联邦学习阶段**。理由见 §5。

## 1. 现状：古典知识的当前承载

| 层         | 载体                              | 数量        | 结构           |
| ---------- | --------------------------------- | ----------- | -------------- |
| 书籍目录   | `data/classical_books.json`       | 699 部      | 书目元数据     |
| 原文切片   | `data/classical_slices.json`      | 613 条      | JSON 数组      |
| 术语映射   | `data/axis_term_mapping.json`     | ~50 条      | 四向映射表     |
| 结构化古籍 | `data/tcm_structured/*.json`      | 613 实体    | 分类 JSON      |

当前切片字段：`book` / `author` / `dynasty` / `entity` / `axis_mapping` /
`retained_bibliographic` / `needs_expert_review`。

**未建关系**：实体之间的语义关联（如"脾"↔"肾"↔"水"↔"冬"）尚未抽取。
当前检索只能按 `axis_mapping` 精确匹配，无法回答"哪些古籍段落讨论脾肾
同病"这类关联查询。

## 2. GraphRAG 化收益评估

### 2.1 理论收益

- **关联检索**：能回答跨实体查询（"脾肾同病的方剂有哪些"）
- **图谱可视化**：中医实体关系图可对外展示为技术壁垒
- **推理增强**：GraphRAG 可基于图结构做路径推理，比向量检索更可控
- **国际化叙事**：可视化知识图谱在 SCI 论文中提升叙事档次

### 2.2 现实收益（诚实）

- **613 条切片太小**——GraphRAG 的优势在万级以上实体量，613 条属于过度
  工程
- **专家审阅未完成**——每条切片 `needs_expert_review=true`，关系抽取前
  需先经人工核实
- **中医实体本体不成熟**——GB/T 20348-2026 术语是"分类词"而非"实体"，
  缺乏标准实体-关系本体；自建本体需要领域专家 6-12 个月
- **无对应基准**——没有公开数据集可对比 GraphRAG vs 向量检索 vs 全文
  检索在中医学场景下的效果

## 3. 成本评估

| 项         | 人月         | 说明                                        |
| ---------- | ------------ | ------------------------------------------- |
| 本体设计   | 3-6          | 定义实体类型 + 关系类型（10-20 类）         |
| 实体抽取   | 4-8          | 613 条切片 × 平均 3-5 实体 + 2-3 关系     |
| 关系抽取   | 3-6          | 基于规则 + 提示工程，需专家校验             |
| 图谱存储   | 1-2          | Neo4j 或 TuGraph 自建                       |
| GraphRAG   | 2-3          | LlamaIndex GraphRAG 或自研                 |
| 前端可视   | 1-2          | Cytoscape.js 或 D3                          |
| 论文叙事   | 1            | 补充"知识图谱"章节                          |
| **合计**   | **15-28**    | **6-12 个月，1-2 人**                       |

**外部依赖**：至少 1 名中医领域专家（100+ 小时审阅）。

## 4. 替代路线对比

| 方案                        | 成本        | 效果           | 推荐？    |
| --------------------------- | ----------- | -------------- | --------- |
| GraphRAG（完全图谱化）     | 15-28 人月  | 理论最强，但过度工程 | ❌ 推迟    |
| 混合检索（向量 + 关键词）  | 3-5 人月    | 覆盖 80% 场景   | ✅ 首选    |
| 关系表（简化 schema）      | 2-3 人月    | 支撑"共同属性"查询 | ⚠️ 备选    |
| 纯全文 + LLM 上下文        | 1 人月      | 快速可用，但精度低 | ⚠️ 过渡    |

**推荐**：走"混合检索 + 关系表"路线，把 GraphRAG 留到 S4 有真实纵向
数据积累后（数据量 >10K 切片）再评估。

## 5. 决策：推迟到 S4

理由：

1. **规模不足**——613 条切片远低于 GraphRAG 的收益门槛（业界经验 ≥ 10K）
2. **专家审阅未闭合**——`needs_expert_review=true` 全部条目，图谱化后错误
   会沿关系放大
3. **本体未成熟**——国标术语是分类词，非实体本体；自建本体需领域专家投入
4. **叙事优先级低于 S1/S2**——当前证据等级 L1，需先补纵向数据（S2-2）
   和真证据 DOI（S1-1 已完成），GraphRAG 是锦上添花
5. **S4 联邦学习自然衔接**——多机构图谱联邦是天然场景，届时图谱规模会
   自然增长到 GraphRAG 收益区

## 6. 过渡方案（当下可执行）

**混合检索最小实现**（3-5 人月）：

```
用户查询
    ↓
[1] 关键词精确匹配（axis_mapping 直查）
    ↓
[2] 向量检索（切片 embedding）
    ↓
[3] LLM 综合（上下文 = top-K 相关切片）
    ↓
回答 + 引用（book + author + dynasty + entity）
```

依赖：
- 一个 embedding 模型（BGE-small-zh 或 SenseNova Embedding）
- 一个向量库（Chroma / Qdrant）
- 现有 `app/lib/fusion_engine.py` 扩展

**关系表最小实现**（2-3 人月）：

```
classical_entities (id, name, type, axis, book, author, dynasty)
classical_relations (from_entity, to_entity, relation_type, source_book)
```

关系类型起步定义（5 类）：
- `complements`（相生）
- `controls`（相克）
- `co_occurs`（共病）
- `transforms_to`（转化）
- `opposes`（对立）

**验收**：能回答"脾与肾的相生病机有哪些古籍来源"这类关联查询。

## 7. 后续触发条件

GraphRAG 化在以下条件**同时满足**时启动：

- [ ] 古籍切片 ≥ 5,000 条
- [ ] 专家审阅覆盖率 ≥ 80%
- [ ] 有明确的关联查询需求（≥ 3 个真实业务场景）
- [ ] 至少 1 名中医领域专家长期投入

## 8. 未闭合（诚实）

- 本报告为**技术选型评估**，未做实证实验（GraphRAG vs 向量检索 vs
  全文检索的对比评测需真实数据支撑）
- 中医实体本体的成熟度评估依赖领域专家意见，本项目暂无外部专家评估
- 混合检索的具体实现方案待 S2 阶段末或 S3 阶段初正式启动
