# HealthLens 依赖锁定文件（D2/H2，2026-10-17）
# =========================================================
# 目的：解决 10-16 全面评估报告指出的 H2 硬伤「无 lock/constraints 文件，
# requirements 全 >= 无上界」——三个月后装出的不是同一个系统，Zenodo DOI 的
# "reproducible" 承诺被架空。
#
# 生成方式（2026-10-17 06:30 本地实测版本）：
#     python -m pip freeze > constraints.txt
# 从 hlcheck venv（Python 3.13.12 + 全部 healthlens 依赖已装齐）导出。
#
# 使用方式：
#     pip install -r requirements.txt -c constraints.txt
# 或：
#     pip install -r constraints.txt
#
# 更新流程（PR 中修改本文件时）：
#   1. 在 requirements.txt 中修改/添加/删除直接依赖
#   2. 删除并重建干净 venv：
#        python -m venv .venv-lock
#        source .venv-lock/bin/activate  (Linux/macOS)
#        .venv-lock\Scripts\activate     (Windows)
#   3. 重新解析依赖并锁定：
#        pip install -r requirements.txt
#        pip freeze > constraints.txt
#   4. 提交 requirements.txt + constraints.txt 两个文件到同一 PR
#
# 验证复现性（CI 步骤）：
#   pip install -r constraints.txt
#   python -c "import hashlib,sys; [print(hashlib.sha256(open(m.__file__,'rb').read()).hexdigest()[:12], m.__name__) for m in [sys.modules['fastapi'], sys.modules['pydantic'], sys.modules['sqlalchemy']]]"
#   # → 每次安装得到相同的哈希前缀 = 字节级一致
#
# 与 pip-compile 的区别：
#   - 我们没装 pip-tools（额外依赖负担），采用 pip freeze 快照方式
#   - 缺点：无 hash 校验、跨平台 wheel 差异（Windows/Mac wheel 不同）
#   - 优点：无需额外工具、CI 与本地一致、可读性强
#   - 升级路径：若需跨平台严格一致性，切换到 pip-compile + --generate-hashes
#
# Python 版本锚定：3.12–3.13（与 pyproject.toml requires-python 一致）
# 平台锚定：当前锁定自 Windows 11（C:/Users/xing/.workbuddy/binaries/python/3.13.12）；
#           Linux/macOS 上 numpy/pillow/cryptography 会选不同 wheel，但版本号一致。
# =========================================================
