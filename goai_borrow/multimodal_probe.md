# 多模态单图原型方案（借鉴 EyeAgent / VisionDoctor）

> 目标：把 HealthLens 的 Demo 完成度从"文本融合"提升到"上传一张舌象/面色/体态图 →
> 八轴倾向速判"，用 EyeAgent 的「工具箱 + RAG 接地 + 自校正」模式，先窄后宽。

## 一、为什么借鉴 EyeAgent

EyeAgent（多模态眼科诊断 Agent，arXiv 2511.09394）的做法可直接迁移：

1. **工具箱模式（53 个验证工具跨 23 模态）**：不靠单一模型硬判，而是把每个专科能力
   做成"工具"，由 Agent Core 按查询动态编排。HealthLens 可把「舌色判别 / 苔腻判别 /
   面色判别 / 体态判别」各做成独立视觉工具。
2. **RAG 接地（14 本教材）**：所有判断回溯到权威知识，降低幻觉。HealthLens 应把
   八轴理论与古籍条文作为 RAG 知识库，视觉判断必须能 cite 到条文。
3. **自校正（self-correction）**：工具给出矛盾结论时，调用二级专科工具复核。
4. **可量化**：消融实验证明工具齐全时准确率 69.71% → 80.79%。

## 二、HealthLens 多模态工具箱（草案）

| 工具 | 输入 | 输出 | 接地知识 |
|---|---|---|---|
| `tongue_color` | 舌象图 | 淡红/红/暗/紫 + 置信度 | 舌诊条文（RAG） |
| `tongue_coat` | 舌象图 | 薄/厚/腻/少苔 + 置信度 | 苔诊条文 |
| `face_color` | 面色图 | 苍白/萎黄/潮红/青 + 置信度 | 望色条文 |
| `body_posture` | 体态/步态图 | 偏颇倾向（如气虚懒言姿态） | 望形条文 |
| `axis_infer` | 上述工具输出聚合 | 八轴倾向（A-H 概率分布） | 八轴理论 |
| `self_check` | 矛盾检测 | 是否触发二级复核 | — |

## 三、编排流程（Agent Core 五步，对齐 EyeAgent）

```
query理解 → tool规划（选哪些视觉工具）→ 执行（并行调用工具箱）→ 结果聚合 → 响应生成
```

- 冲突处理：若 `tongue_color=红` 但 `face_color=苍白` 矛盾，触发 `self_check` +
  二级 `axis_infer` 复核，输出"不确定，建议结合问诊"。
- 所有视觉结论必须附 **RAG 条文引用**（呼应 multi_agent_roles.md 的引用溯源）。

## 四、落地路径（先窄后宽）

1. **MVP（2 周）**：仅做 `tongue_color` + `tongue_coat` 两个工具 + 八轴映射，用公开舌象
   数据集做小样本校验（目标：与人工判读一致率 ≥ 基线）。
2. **扩展**：加入 `face_color` / `body_posture`，形成多图联合推断。
3. **闭环**：视觉结论 → 融合引擎 → 非用药建议 → 回写案例库（SIIV 的 V 端）。
4. **硬件远期**：SmartSports X / Rokid 式可穿戴+HUD 实时反馈（见评估建议维度 5）。

## 五、风险与护栏

- 视觉判断**不得作诊断**，仅作"八轴倾向速判"，必须过 `agent_safety_gate` 两道闸门。
- 模型权重若走本地（本机无 NVIDIA，见用户环境事实），优先用 CPU 友好小模型或云端 API；
  严禁把用户健康图像发往未授权外部服务（runtime_audit 的 unauthorized_external_service 拦截）。
- 数据集需去标识化（呼应安全合规维度）。
